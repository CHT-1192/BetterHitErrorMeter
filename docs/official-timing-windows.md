# ADOFAI 官方判定窗口文档

> 来源：7thbeat (游戏开发者) 的 Notion 页面 "Timing Window Calculations"
> 这是官方对判定窗口机制的标准解释

---

## 核心概念

判定窗口本质上是**基于角度**的。每次按键时，游戏计算行星当前角度和目标砖块出口角度之间的差值，然后按角度范围划分判定等级。

### 角度区间

| 角度差 d | 判定 |
|----------|------|
| d < -60° | Too Early (太早) |
| -60° ≤ d < -45° | Very Early (很早) |
| -45° ≤ d < -30° | Early Perfect (早完美) |
| -30° ≤ d ≤ +30° | Perfect (完美) |
| +30° < d ≤ +45° | Late Perfect (晚完美) |
| +45° < d ≤ +60° | Very Late (很晚) |
| d > +60° | Too Late (太晚) |

> 正角度 = 行星已经越过出口 = Early（早），负角度 = Late（晚）

### 角度转毫秒公式

```
毫秒 = 角度° / BPM × (1000/3)
```

**例子（180 BPM）**：
- 60° → ±111ms
- 45° → ±83ms
- 30° → ±56ms

**问题**：BPM 越高，时间窗口越窄。比如 700 BPM 时 60° 只剩 ±29ms，太严了。

---

## 保险机制 1：BPM 上限

到达某个 BPM 后，不再继续缩小判定窗口——用 BPM 上限值代替实际 BPM 来计算。

### 三种难度

| 难度 | BPM 上限 | 实际值 | 最低时间窗口 |
|------|:------:|:------:|:----------:|
| 普通 | ~220 BPM | 219.78 | ±91ms |
| 严格 | ~310 BPM | 307.69 | ±65ms |
| （游戏最初无难度选择时） | ~500 BPM | 500 | ±40ms |

- 普通：BPM 超过 ~220 后，一律按 220 BPM 算，时间窗口固定 91ms
- 严格：BPM 超过 ~310 后，一律按 310 BPM 算，时间窗口固定 65ms
- 官方关卡目前只有普通和严格两种可选

### 难度选择不影响低 BPM

在 BPM 低于上限的关卡中，所有难度的判定窗口完全相同。只有高 BPM 关卡才会有区别。所以官方关卡里开启难度选择后，只有 340 BPM 以上的关卡才会显示难度切换按钮——BPM 不够高时切换了也没差别。

---

## 保险机制 2：25ms 硬下限

不管什么情况，**所有判定类型的窗口都不会低于 25ms**。

这个硬下限覆盖 Counted、Perfect、Pure 三种判定层级。实际中它只影响最高难度（上限 500 BPM）下的 Pure Perfect 判定——在某些极端 BPM 下 Pure 窗口会被卡在 25ms，而不是继续缩小。

---

## 飚速（Speed Trial）

飚速不是把倍率乘到 BPM 上，而是**直接缩小已经算好的判定窗口**：

```
飚速后的窗口 = 正常窗口 × (1 / 飚速倍率)
```

这意味着飚速比单纯提高 BPM 更难——同样的判定窗口在更高的转速下更难命中。而且 25ms 硬下限依然有效：在高飚速倍率下窗口可能被卡在 25ms，导致多个判定等级被合并。

**例子**：150 BPM × 5 倍飚速，判定极端严苛，某些难度下只剩下 Perfect 一个判定。

---

## 移动版

移动版**不使用 BPM 上限机制**。替代方案：
- 判定窗口有更宽的固定时间值
- 飚速倍率**直接乘在 BPM 上**，而不是缩小已计算的窗口

---

## 判定窗口缩放事件（Timing Window Scale）

Neo Cosmos 版本新增的功能，允许关卡制作者创建缩小或放大判定窗口的自定义事件。

缩放直接乘到每个判定的角度值上。例如 50% 缩放 → 60° 变 30°，45° 变 22.5°，30° 变 15°。

但缩放**不影响** BPM 上限和 25ms 硬下限这两个保险。如果缩放后计算出的窗口小于保险的值，使用保险的值。

---

## 最终判定窗口的决定过程

1. 用固定角度值（60°/45°/30°）乘以 BPM 转成毫秒
2. 检查 BPM 是否超过难度对应上限 → 超过则用上限 BPM
3. 应用飚速倍率 → 除以飚速倍率
4. 应用判定窗口缩放 → 乘以缩放百分比
5. 检查 25ms 硬下限

最终窗口 = max(计算值, 25ms)

---

## 官方案例：300 BPM + 50% 缩放

原始窗口：60° / 300 × 1000/3 ≈ ±67ms

乘以 50% 缩放 → ±33ms

但因为还有 BPM 上限保险（取决于难度选择），最终结果会是计算值和保险值中的较大者。
